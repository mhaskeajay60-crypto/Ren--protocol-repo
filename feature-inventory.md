# The Ren Protocol — Complete Feature Inventory

## Quick answer

The Ren Protocol currently contains **77 named author-facing workflows and safeguards**. This is a workflow count, not a button count: for example, **Masterbook Atlas** is one major system with several record types, while **Player Backup** is one focused backup flow with export, preview, and safe separate-copy restore.

The app has grown in stages. Almost no useful feature was deleted. Most apparent “removals” were actually **renames, layout replacements, or moving repeated shortcuts into clearer places**. The active app is designed for personal browser-local use first, with an optional protected Team space kept separate.

> **The most important rule:** nothing silently writes the novel, changes a Masterbook fact, sends private material, deletes a record, or makes shared canon.

## What was changed, renamed, or moved

The list below is important because a feature can feel “removed” when its name or doorway changed. In these cases, the capability was preserved or improved rather than deleted.

| Earlier version | Current version | What happened |
| --- | --- | --- |
| Dump Book | Story Vault | Renamed to feel like a safer private story intake. The underlying capture, tags, filters, files, and organization tools remain. |
| Plain Masterbook lists | Masterbook Atlas | Replaced with category-first visual destinations, dossiers, and guided creators. Existing records remain valid. |
| Long phone navigation | Pocket Story Console dock + More | Replaced to make phone use calmer. Secondary tools are still available through More and All tools. |
| Repeated big shortcuts | Feature Map and grouped navigation | Duplicated doors were reduced so the same task does not appear everywhere. No core tool was intentionally removed. |
| Long generic forms | Progressive builders | Essential first fields stay visible; optional advanced details are behind an extra step. |
| Hidden PDF importer | Direct Write actions | PDF import is now visible as Import chapter PDF and My PDF imports. |
| Simple first Relationship Web | Focus Thread + Bond Ledger | Extended with visible reader knowledge, pressure points, and chapter context. |
| Old pale mobile cards | Dark Pocket Story Console | Replaced with larger touch targets and a focused five-place phone layout. |

## What was deliberately **not** added or is still paused

These are not missing by accident. They are held back to protect privacy, story control, or the project’s simple personal purpose.

| Not active | Why it is not active |
| --- | --- |
| Automatic canon creation from chapter prose | It could mistake a temporary idea for official world truth. Current Masterbook updates are private suggestions only. |
| Automatic sending while typing or uploading | The author must always see and approve what leaves the browser. |
| Automatic local-to-Team sync | Private writing and group canon are deliberately separate. |
| Unapproved cloud storage of all writing | The main workspace remains browser-local; backup export is explicit. |
| Full generated product-tour video | The storyboard and one safe 8-second opening clip exist, but full video generation is paused by the current free daily limit. |
| Large commercial collaboration system | The app supports a small protected group, not an open social writing platform. |
| A role literally named Lore Keeper in the database | The existing protected Ruler role is shown as the approval authority; no new risky role was silently created. |

## The accurate total

The tables above identify **77 named current workflows**. If several related review sub-tools and safety checks are each counted as their own separate feature, the practical total is **well over 80**. The simplest accurate answer is therefore: **77 named capabilities, plus smaller related controls and safeguards.**

The number alone is less important than the structure: everyday work has a simple entry point, advanced tools are findable, and every powerful action remains review-first and author-controlled.
